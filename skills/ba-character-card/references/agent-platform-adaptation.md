# 角色接入 AstrBot、DSH 与 SillyTavern

按用户选定的宿主制作适配包。先核对安装版本、接管对话的插件、当前配置及会话绑定，再选下列路径；不要默认给每个平台各做一份，也不要把这份技能本身当成角色卡安装。未授权部署时交付文件和操作说明，已授权则继续完成对应配置与验证。

本次资料核对日期：2026-11-08。下方 DSH 指 DeepSeek Harness；同名工具、第三方酒馆插件及旧版本须另外确认。界面位置和字段以用户安装版本为准。

## 先分清要装什么

| 内容 | AstrBot 原生 / mem_chat | DSH 原生 | SillyTavern（酒馆） |
|---|---|---|---|
| 基础身份、动机、经历、关系、说话习惯 | 人格系统提示 / 插件的人设正文 | 当前 agent 预设中的 persona prefix | description、personality、scenario |
| 少量新写对话示范 | 预设对话或人设示例，标明双方身份 | persona 内的短示例或已支持的上下文模块 | mes_example；开场另放 first_mes |
| 原作场景、细节与梗资料 | 指定知识库 / 角色专用 RAG | 已安装且可被该 agent 使用的检索或资料读取机制 | Character Lore / World Info |
| 群友偏好、互动经历 | 绑定实际用户、会话与角色的记忆 | 核对该会话实际使用的记忆插件与范围 | 当前聊天记录及实际启用的记忆扩展 |
| 调度、JSON 协议、工具权限 | 留给宿主或插件实现 | 留给运行时和已配置插件 | 留给前端与模型预设，不从 mem_chat 照搬 |

同一份人格底稿可以复用，平台控制协议不能原样互贴。知识检索与身份设定分别配置；关键身份和关系不能只藏在可能未触发的知识条目中。转换后保留原稿、出处及原有扩展字段。

## AstrBot 原生人格

适合由 AstrBot 内置 AI 直接处理对话的部署。若实际由 mem_chat 或第三方 Agent 接管，先读下一节或该执行器的说明，确认谁最终组装模型请求。

1. 在 WebUI 的“人格设定”中新建专用人格，填写基础人设；有预设对话时把用户与助手角色分清，不把整段原作多角色剧情当成助手示范。不要用已废弃的旧版 persona 配置项代替当前人格管理。
2. 在目标配置文件的 AI / 人格设置中选中它。只改一个群或私聊时，可在支持该功能的版本中通过“自定义规则”覆盖该消息来源的人格；修改后核对实际 persona_id，不能只凭人格名称或账号昵称判断。
3. 资料较多时，在“模型提供商”配置嵌入模型，创建角色知识库并上传整理后的检索文本。等待解析、分块和嵌入完成，先用知识库检索页核对命中内容。
4. 在该配置的 AI → 能力 → 知识库中选用它；按会话单独选库时使用对应自定义规则。检查全局与会话覆盖是否仍选中了另一个角色的库。聊天模型与嵌入模型分别配置。
5. 验证实际聊天请求包含正确人格和检索片段。普通检索与 Agentic 工具检索的触发不同，启用 Agentic 不代表每轮一定调用；跟进消息不含关键词时，也要检查历史与召回能否续接。

多人共享账号时，显示昵称不等于角色身份。只为指定会话改人格时，不修改默认人格、其他群的会话规则或整个账号名字来冒充隔离。

依据：[WebUI](https://docs.astrbot.app/use/webui.html)、[自定义规则](https://docs.astrbot.app/use/custom-rules.html)、[知识库](https://docs.astrbot.app/use/knowledge-base.html)、[当前配置参考](https://docs.astrbot.app/dev/astrbot-config.html)。

## AstrBot + mem_chat 等接管插件

这是检查和适配现有插件的路径，不是所有 mem_chat 版本都支持同一套键名。先读插件 README、配置 schema 和实际组装提示 / 检索的代码，再产生该版本可用的配置。

- **入口与绑定：** 找到人设文件、状态规则、角色资源选择器和按群覆盖逻辑。若本地实现有 persona_profile、group_persona_overrides，确认有效角色值及实际支持范围；不存在这些字段就不要只往 JSON 里加同名键。支持新角色可能需要实现适配。
- **所有提示层：** 检查基础人设、at / focus / read_air、自称、唤醒别名、宿主预设对话、工具说明和图片筛选提示。旧角色提示不能在后续层重新覆盖新角色；固定状态键可以兼容保留，但按新角色解释。
- **检索隔离：** 查清语料扫描目录、分块器、角色类型或命名空间、向量索引过滤条件及缓存哈希。保留剧情阶段、说话人和分支；角色资料不能误导入另一个角色的全局库。不要把备份、说明文档或旧版本放进正式扫描目录。
- **索引完整性：** 对比预期块数与实际可用向量。部分嵌入成功不能记作整库完成；失败应保留可续建状态。实际检索要命中正确角色，不能只验证文件存在或导入日志。
- **历史与记忆：** 切换时保留用户要求保留的记录，同时说明旧角色的台词不是新角色自身经历。亲密关系、用户偏好与角色关系分别核对；不要靠清空所有历史来掩盖串角色。
- **模型与媒体：** 主模型、备用模型使用一致的当前人设。图片识别、表情检索和发送结果分别验收；记录实际发送的图片，而不是把检索意图当作图片事实。

交付该版本的资源布局、准确的配置改动、索引状态与恢复方法。只有已获部署授权时才写运行配置、建向量或重载服务；具体测试群和测试账号也以授权范围为准。

## DSH / DeepSeek Harness

### 官方原生 persona 预设

本段按官方源码提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 核对；实际部署先确认版本和已安装包。新版本或第三方插件有变动时重新读 schema，不凭旧教程猜字段与目录。

官方提供作用域内的 `@deepseek-ai/dsh-persona`。它通过 prefix / suffix 替换当前 agent 的人格段，不应直接挂到全局。下面是 entry-list 形式的最小预设声明，**不是完整的 DSH 部署配置，也不是任意设置框都接受的输入**：

```yaml
- id: preset-ba-character
  name: '@deepseek-ai/dsh-agent-preset'
  config:
    id: ba-character
    plugins:
      - name: '@deepseek-ai/dsh-persona'
        config:
          prefix: |-
            你是目标角色。这里替换为已整理的人设正文。
            使用角色本人的自称；按当前发言人的实际身份称呼。
            原作场景保留说话人和剧情阶段，不继承其他角色的台词。
          complete: false
```

这是只说明人格挂载位置的示例，不含模型连接、鉴权和消息渠道。需要沿用原有工具或记忆模块时，检查现有预设并保留所需插件行，再增加或替换 persona；新的 plugins 列表不会自动继承默认预设的全部模块。

- 当前官方预设由声明式插件行注册，不由扫描角色目录自动发现。桌面版按该版本支持的 Creator / plugin_manager 流程生成并安装 bundle patch；自己管理 Cordis 配置时按其实际入口合并。不能把这段 YAML 宣称为已安装的预设。
- 在新测试会话中明确选择 ba-character 预设并核对绑定。已有运行中的 agent 可以继续保留旧组合，不能因定义已保存就宣布旧会话已切换，也不必为测试删除旧聊天记录。
- 默认保持 complete: false。true 会把 prefix 变成唯一的系统提示，排除其他提示段；不是为了“角色更像”就可以开启的普通开关。除非用户明确需要完整替换且已核对影响，保留运行时提示。
- prefix / suffix 中的双大括号由 DSH 按已注册变量严格解析。不要把酒馆的 {{char}}、{{user}} 等宏直接搬进来；导出时替换为确定的角色名、明确的发言人标记，或使用该安装版本支持的变量。
- 原作检索不由 persona 包自动提供。检查实际安装的文件读取、记忆或 RAG 机制及该 agent 的访问范围；没有相应能力时交付短版人格和单独资料，明确尚未接入检索。

依据：[persona 配置与边界](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/preset/persona/README.md)、[预设注册与会话绑定](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/preset/agent-preset-registry/README.md)、[配置目录](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/config-catalog.md)。

### DSH 上的酒馆兼容插件

先记录插件仓库、安装版本、导入格式和实际负责拼装提示的组件。同名“酒馆插件”不等于同一实现，官方 persona 预设也不能因此被当成 Character Card 加载器。

如果插件明确支持 Character Card V2，可以使用下一节的字段映射生成 JSON，但仍需逐项核对它支持的世界书触发、宏、示例、正则与扩展字段。不要同时启用两套互相冲突的身份提示。未支持的功能列为缺口，不捏造配置开关；有现成导出样本时优先保留其原格式，再替换已确认的字段。

## SillyTavern / 酒馆

这里指 SillyTavern，不把所有名为 Tavern 的站点或角色包当成同一种格式。先确认目标版本和用户要的卡格式；新做兼容包可采用 V2，已有其他版本或私有扩展时保留原包与未知字段，不无声降级。

### 制作并导入角色卡

可复制 [V2 JSON 模板](../assets/sillytavern_v2.template.json) 到角色项目中填写。模板只有通用示例，不含任何角色的正式成品；它不是 PNG 图片卡，也不是完整酒馆配置或模型预设。

| V2 data 字段 | 放什么 | 注意 |
|---|---|---|
| name | 用户选定的角色名 | 译名保持一致 |
| description | 核心身份、外貌、默认剧情阶段和关系 | 关键事实放正文，不能只写在作者备注 |
| personality | 动机、判断习惯、情绪与口吻摘要 | 不复述整份背景 |
| scenario | 默认见面场景及当前双方关系 | 不把所有用户预设成老师或恋人 |
| first_mes / alternate_greetings | 开场及备选开场 | 按目标短聊或长聊风格新写 |
| mes_example | 少量对话示例 | 用 <START> 分隔，标记 {{user}}: 与 {{char}}:；标明新写示范 |
| creator_notes | 来源、改编与使用说明 | 不参与模型提示构建；不把必需人格藏在这里 |
| system_prompt / post_history_instructions | 确有需要的提示覆盖 | 模板默认留空；核对宿主 Prefer Char. Prompt / Instructions 设置 |
| character_book | 随卡嵌入的角色世界书 | 不等于所有版本独立 World Info 文件的序列化格式 |
| extensions | 原有扩展数据 | 修改旧卡时保留未知字段 |

填好后在角色管理中导入 JSON，检查字段和世界书，再新建测试聊天。若要求 PNG 卡，使用已核实的卡片导出工具或前端导出并验证可重新导入；仅给图片改后缀不构成卡片嵌入。

### 角色世界书与资料触发

- 按人物关系、事件、设定和相关梗拆成自足短条，保留必要的阶段与出处；人设核心放常驻角色字段，长资料按需进入世界书。
- 为关键词补角色译名、别名和相关称呼。重要说明、事实和阶段写进条目 content，不只写在标题、comment 或 keys 中；这些元数据不能代替正文。
- 在 World Info 中创建 / 导入对应资料，并在角色管理中用角色世界书入口绑定。核对全局、角色、用户 Persona 和聊天级世界书的叠加，避免另一个角色的资料也被触发。
- 新用户与首次验收可先测直接关键词，再用省略关键词的连续追问测试扫描范围、预算及已启用的延续机制。检索成功过一次不保证后续每轮都保留；不要把世界书描述成永久记忆或默认向量 RAG。
- scan_depth、token_budget、递归、延迟或黏性等字段以实际前端支持为准。模板中的扫描与预算只供起步测试，不是推荐给所有模型的固定值；只调整能解释当前失败的项。
- 角色卡内的 character_book.entries 是 V2 数组结构。独立 World Info 文件应取该版本真实导出作模板，不能只把嵌入结构改名后就宣布可导入。

依据：[角色字段与示例](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)、[World Info 触发与绑定](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)、[Character Card V2 规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)。

## 接入后的最小验收

按改动挑选有意义的场景。用户授权在线测试时，才使用实际目标群或会话发消息；不要为了验证技能而擅自发到用户的群里。验证记录分为文件可解析、成功导入、实际请求包含、模型回复符合设定四层。

| 场景 | 核对内容 |
|---|---|
| 自我介绍、错误名字、账号旧昵称 | 当前角色、自称与称呼稳定；展示名不改写身份 |
| 原作经历及人物关系 | 阶段正确，能区分其他角色，不把分支与选项全当已发生 |
| 普通群友与老师分别聊天 | 关系绑定正确，用户纠正身份后能更新 |
| 熟人玩梗、纠正错误设定、转回日常 | 梗不改写事实，不在玩笑结束后持续表演 |
| 先命中资料，再连续追问 | 看每轮实际上下文、召回与预算，不靠猜测“应该查过” |
| 同一账号的另一群、私聊及另一角色 | 目标绑定与记忆隔离符合需求，默认角色未被误改 |
| 主接口故障后备用接管 | 沿用当前角色与上下文，不更换身份或漏掉关键约束 |
| 发送图片或表情后追问 | 回答依据实际发送内容；选图贴切度和发送成功分别判断 |

宿主没有对应功能时注明“不适用”，而不是模拟一项不存在的测试。报告实际版本、改动与绑定范围、检索命中、延迟或故障、剩余缺口和恢复办法；配置截图、文件校验或短聊都不能替代长期效果证明。
